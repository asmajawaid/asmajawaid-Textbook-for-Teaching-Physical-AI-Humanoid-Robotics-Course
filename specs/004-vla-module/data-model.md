# Data Model for Module 4: Vision-Language-Action (VLA)

This document outlines the key data entities and their relationships relevant to the "Vision-Language-Action (VLA)" chapter. These entities represent the core components and data flows within a VLA robotics system.

## 1. VLA (Vision-Language-Action) Pipeline

The overarching system orchestrating the flow from multi-modal input to robotic action.

-   **Components**:
    -   **Speech-to-Text Module**: Converts spoken language to text (e.g., OpenAI Whisper).
    -   **Language Understanding Module**: Interprets text commands, often powered by an LLM.
    -   **Task Planner Module**: Generates high-level task plans using an LLM.
    -   **Action Sequencer Module**: Translates task plans into executable robot actions.
    -   **Robot Controller**: Executes low-level action primitives (often via ROS 2).
    -   **Perception Module**: Processes visual or other sensor data (e.g., object detection).
    -   **Feedback Mechanism**: Provides robot status or requests clarification.
-   **Data Flow**: Audio -> Text -> LLM Prompt -> Task Plan -> ROS 2 Actions -> Robot State -> Visual/Sensor Feedback -> LLM Prompt (for re-planning/clarification).

## 2. Task Plan

A structured sequence of high-level steps generated by an LLM, representing the robot's intended actions to achieve a user's goal.

-   **ID**: Unique identifier for the plan.
-   **Goal**: The natural language instruction provided by the user (e.g., "pick up the red cube").
-   **Steps**: An ordered list of actions to be executed. Each step is typically an `Action Primitive`.
    -   **Step ID**: Unique identifier within the plan.
    -   **Action Primitive Name**: Reference to an `Action Primitive` (e.g., `navigateTo`, `grasp`).
    -   **Parameters**: Key-value pairs providing specific details for the action (e.g., `object_id='red_cube'`, `target_location=(x, y, z)`).
    -   **Dependencies**: Optional, defines steps that must be completed before this step.
    -   **Success Condition**: Criteria to determine if the step was successfully executed.
    -   **Failure Condition**: Criteria to determine if the step failed.
-   **Status**: Current execution status (e.g., `pending`, `in_progress`, `completed`, `failed`, `aborted`).
-   **Context**: Information about the environment or robot state relevant to the plan.

## 3. Action Primitive

A low-level, atomic, pre-defined, and safe robot capability that can be invoked by the action sequencer. These form the robot's "vocabulary" that the LLM can use.

-   **Name**: Unique identifier (e.g., `navigateTo`, `grasp`, `pick_up`, `place_down`, `wave_hello`).
-   **Description**: Natural language explanation of what the primitive does.
-   **Parameters**:
    -   **Name**: Parameter name (e.g., `target_location`, `object_id`).
    -   **Type**: Data type (e.g., `geometry_msgs/Pose`, `string`, `int`).
    -   **Constraints**: Valid range or acceptable values.
-   **ROS 2 Interface**: The corresponding ROS 2 topic, service, or action that implements this primitive.
    -   **Type**: `topic_pub`, `service_call`, `action_goal`.
    -   **Name**: ROS 2 interface name (e.g., `/nav2/navigate_to_pose`).
    -   **Message Type**: ROS 2 message/action type.
-   **Pre-conditions**: Conditions that must be true before the primitive can be executed safely.
-   **Post-conditions**: Expected state changes after successful execution.
-   **Safety Constraints**: Inherent safety checks or limits (e.g., joint limits, maximum speed).

## 4. Prompt Template

A structured input format used to query an LLM, providing context, available tools/actions, current state, and the user's request.

-   **Name**: Identifier for the template.
-   **Purpose**: What kind of query it's designed for (e.g., `task_decomposition`, `error_recovery`, `clarification_request`).
-   **Structure**:
    -   **System Role**: Defines the LLM's persona and responsibilities (e.g., "You are a helpful robot assistant. Generate a plan.").
    -   **Available Tools/Actions**: List of `Action Primitives` the LLM can use, with their descriptions and parameters.
    -   **Current State**: Information about the robot's current pose, object locations, sensor readings.
    -   **User Instruction**: The transcribed natural language command from the user.
    -   **Constraints/Guidelines**: Safety rules, formatting requirements for the output plan.
    -   **Example Dialogue/Few-shot examples**: Demonstrations of desired input/output.
-   **Output Format**: Expected structure of the LLM's response (e.g., JSON, markdown list of actions).

## 5. Speech Input

The raw audio data from a human voice command.

-   **Audio Stream**: Raw audio data.
-   **Timestamp**: Time of recording.
-   **Speaker ID**: Optional, if multiple speakers are identified.

## 6. Text Transcription

The textual representation of the speech input, produced by a Speech-to-Text module.

-   **Text**: The transcribed text (e.g., "pick up the red cube").
-   **Confidence Score**: Probability of correctness.
-   **Timestamp**: Time of transcription.

## 7. Robot State

The current physical and environmental state of the robot and its surroundings.

-   **Robot Pose**: Position and orientation of the robot base and individual joints.
-   **Object Locations**: Detected positions and identities of objects in the environment.
-   **Sensor Readings**: Current data from cameras, LiDAR, IMU, etc.
-   **Internal Status**: Battery level, error flags, mode of operation.
-   **Semantic Map**: High-level understanding of the environment (e.g., "kitchen", "table").
